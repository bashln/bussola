# Decisions

- Product: curated content + linked skill matrix (Odin-style) with radar/roadmap; sandbox/auto-grading and hosted video rejected for v1.
- Leveling: hybrid — manual baseline via sliders on `/skills` plus lesson completions; prereqs consultative (no locks); default target level 5 so roadmap never empty; content public, progress requires GitHub login; static delivery notes in MDX; no wizard.
- Level formula: `limiares[baseline-1] + pesos` chosen because the spec's literal formula contradicted its own example (slightly slower growth from a manual baseline).
- Stack: Next.js/TS/Tailwind/Auth.js/Neon Postgres+Drizzle; PT-BR; v1 = Foundations + Node/backend only.
- Drivers: PGlite in tests, postgres.js in prod; lazy `getDb()`.
- Repo: public `bashln/bussola`, branch `main`, work in place.
- Rename: "Bússola" is product identity; "hardskills" only the matrix concept; no schema/route/model change.
- Model budget: free model; subagents inherit session model; no paid model pinned; no external LLM CLI (agy / Gemini 3.8 flash) without explicit user authorization.
- **Env-var naming caution:** `docs/deploy.md`/runbook use `AUTH_GITHUB_ID` / `AUTH_GITHUB_SECRET`; the final secure form asked for `GITHUB_CLIENT_ID` / `GITHUB_CLIENT_SECRET` (plus `DATABASE_URL`).
